## 3. Contrato de erro corrigido

O contrato publico `ApiErrorResponse` foi preservado: TraceId, Code, Message, Details, com header X-Correlation-ID existente.
Nenhum corpo HTML upstream e baixado ou registrado pelo cliente HTTP .NET em respostas nao-2xx.
As mensagens publicas sao seguras e nao incluem chaves, payloads de usuarios, HTML ou detalhes do provedor.

| Falha | Code | HTTP da API |
|---|---|---|
| Upstream 502 ou outro erro nao classificado | ia.upstream_bad_gateway | 502 |
| Chave interna rejeitada: upstream 401/403 | ia.upstream_authentication_failed | 502, nao 401 da sessao do usuario |
| Upstream 503/429 ou conexao indisponivel | ia.servico_indisponivel | 503 |
| Deadline ou upstream 408/504 | ia.servico_timeout | 504 |
| JSON invalido/nulo, contrato invalido, sucesso HTML | ia.resposta_invalida | 502 |
| BaseUrl ausente | ia.servico_nao_configurado | 503 |
| Violacao clinica real ou validacao de entrada | Codigo de negocio existente | Comportamento de negocio preservado, inclusive 400 |

O timeout cobre recebimento de headers **e leitura do JSON**, respeita cancelamento do cliente e o menor timeout configurado.
Falhas de infraestrutura saem antes de fallback/guard/persistencia nos handlers Coach, texto alimentar, planos e treinos.
Reconhecimento por imagem, rotulos e demais consumidores preservam a propagacao dos erros classificados.
Fallback deterministico retornado com sucesso pelo Python continua disponivel; nao foi habilitado fallback automatico entre provedores.
Revisao humana das estimativas nutricionais e controles clinicos foram preservados.

### Retry

Nao foi adicionado retry automatico de POST. Uma falha apos envio pode ter produzido geracao paga sem entregar a resposta; repetir pode duplicar custo/operacao.
Os testes confirmam uma unica tentativa por requisicao.
Retry futuro: avaliar GET de disponibilidade com deadline total, poucas tentativas e backoff; para POST exigir primeiro idempotencia comprovada de ponta a ponta.
Isso nao resolve a disponibilidade de um servico suspenso e nao deve ser habilitado como substituto de capacidade/monitoramento.
O middleware atual de idempotencia armazena apenas respostas 2xx: 502/503/504 nao ficam presos no cache.
A janela de concorrencia da idempotencia, registrada na auditoria geral, continua pendente.
